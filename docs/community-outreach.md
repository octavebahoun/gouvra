# Community outreach

Ce document transforme la stratégie de diffusion en plan exécutable pour faire connaître Gouvra.

## Objectif

Positionner Gouvra comme **control room open source et self-hosted pour agents IA** auprès des
communautés les plus proches du besoin.

## Priorités de communautés (ordre d'exécution)

1. **Builders d'agents IA (indie + startups)**
2. **DevOps / Platform / SRE orientés IA**
3. **Communauté open source self-hosted**
4. **Équipes techniques en scale-up/PME**
5. **Profils sécurité/compliance**

## Messages par communauté

### 1) Builders d'agents IA
- Message principal : **« Contrôler les runs, coûts, erreurs et outils en live. »**
- Canaux : X/Twitter, Discord IA, Reddit (LLM/agents), Hacker News.

### 2) DevOps / Platform / SRE orientés IA
- Message principal : **« Self-hosted, sécurité, audit, sandbox, workflows. »**
- Canaux : communautés Kubernetes, self-hosting, observability, Platform Engineering.

### 3) Open source self-hosted
- Message principal : **« Alternative open source pour opérer des agents en équipe. »**
- Canaux : forums self-hosted, Awesome lists, Product Hunt (open-source), GitHub discovery.

### 4) Équipes techniques scale-up/PME
- Message principal : **« Passer du POC agent à une exploitation fiable. »**
- Canaux : LinkedIn tech, meetups IA/engineering, communautés Slack orientées builders.

### 5) Sécurité/compliance
- Message principal : **« Isolement des outils code, gestion des secrets, traçabilité. »**
- Canaux : AppSec/SecOps, communautés RSSI techniques.

## Plan d'activation initial (4 semaines)

La séquence démarre par les communautés **1** et **2**.

### Semaine 1 — Préparation
- Préparer une démo courte orientée « run en échec → diagnostic ».
- Préparer 2 messages fondateurs (builders + DevOps/SRE), chacun avec un angle clair.
- Préparer des visuels issus de `docs/images`.

### Semaine 2 — Lancement communautés 1
- Publier sur X/Twitter et 1-2 Discords IA.
- Publier un post Reddit ciblé agents/LLM.
- Ouvrir un thread Hacker News si la démo est prête.

### Semaine 3 — Lancement communautés 2
- Publier dans communautés Kubernetes/self-hosted/observability.
- Insister sur architecture, sécurité, audit et sandbox.
- Répondre rapidement aux retours techniques (questions d'isolation, coûts, limites).

### Semaine 4 — Consolidation
- Reprendre les meilleurs retours utilisateurs en preuve sociale.
- Ajuster le message principal selon les objections récurrentes.
- Étendre vers la communauté 3 (open source self-hosted).

## Indicateurs à suivre

- Nombre de visites sur le dépôt GitHub et étoiles gagnées.
- Nombre d'installations locales/démos lancées.
- Nombre de conversations qualifiées par communauté (issues/discussions/DM).
- Taux de conversion « curiosité → essai » (clics vers README / docs / quick start).
